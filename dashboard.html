Project documents & data practice

Requirements come from Project Pakshi JKLU Concept and Project Pakshi Jaipur Conservation Network Proposal: repeat surveys, effort recording, habitat assessment, an initial DHS pilot, and careful distinction between field and external records.

Published markers use approximate site positions with 1–5 km uncertainty. Smriti Van, Kishan Bagh, Nevta Dam and Nahargarh Biological Park have linked OpenStreetMap geographic references; other area positions are approximate working positions, mostly retained from the supplied HTML, and need field confirmation. The St. Xavier’s marker represents the Nevta campus area, not a surveyed campus coordinate. Habitat candidates have no occurrence claim.

Field data and habitat logs are stored in the current browser, or your configured Supabase project. Photos are resized and re-encoded before storage to remove embedded location metadata. Sensitive submissions generalise coordinates, replace the site label, and omit notes and photos. Only upload images you may share.

Ready for a field survey

  1. Create a browser-local account, or connect a Supabase project first.
  2. Choose a species and record date, count and effort.
  3. Use GPS, enter coordinates or choose a point on the map.
  4. Add a photo if appropriate. Flag uncertain identification.
  5. Return to the same site and record comparable effort.

To enable shared accounts

  1. Create your own Supabase project and run the downloaded SQL.
  2. Enable Email auth. Set your hosted HTTPS Site URL and permitted redirects.
  3. Paste the project URL and public browser key, select Supabase, then save.
  4. Create an account and confirm your email if the project requires it.

Where your data lives

Local mode uses IndexedDB. It is a functional device-local prototype, not a security boundary between people sharing a browser. Passwords are salted and derived with PBKDF2. Clearing browser data removes local accounts and records.

Cloud mode uses Supabase Auth and row-level policies. Authenticated participants can read project field records; only their authors can change or delete them. This file does not deploy a backend or supply credentials.

Portable data

CSV and GeoJSON exports include your filtered field records without account details, keys or photos. Keep a backup before moving browsers.
